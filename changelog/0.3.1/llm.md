## Docs shell (docs site only)

This affects agents editing `apps/docs`, not apps that use `@mielui/svelte`.

The docs shell no longer has a dark frame, an icon rail, a plate around the page, a sidebar collapse button, a Cmd/Ctrl+B shortcut, sidebar resizing, pages that fill the whole panel, or the tab dock with its open-page tabs. Do not bring any of them back. The page color is the background, and one borderless sidebar at the start holds the brand, GitHub, the theme toggle, and the search field (`shell/sidebar-top.svelte`). The root layout renders the docs sidebar on every page except the homepage, Studio included. Studio puts its settings panel after its preview with `<Sidebar wide>`, so it sits on the right; never replace the docs sidebar with a page's own panel. Below the large breakpoint the sidebar is hidden and `shell/header.svelte` takes its place, so only one `.brand` is visible at any width. The brand carries the `brand` view-transition name, which must stay unique on screen.

Group identity comes from `shell/look.ts`. Use `lookFor(pathname)` for a page's group, `groupLook(id, title, href)` for a component group, and the `mesh` palette for colors. Render the group with `shell/sticker.svelte`, inside a `group/section` element so it springs on hover. Do not pick new gradient colors inline. `PageIntro` already draws the sticker label and the `.mesh-glow` tint, and `DocsPager` draws sticker tiles, so a page only passes its title and lead.

The site look lives in plain classes in `apps/docs/src/app.css` under `@layer components`: `.wrap`, `.tile`, `.display`, `.accent`, `.grain`, `.dusk`, `.sunrise`, `.mesh-glow`, `.stagger` with `[data-rise]`, `.press`, `.press-soft`, `.link`, `.key`, `.glow-plain`, and `.glow-white`. `app.css` only references `ui.css`, so an `@utility` added there emits nothing; add a plain class instead. Because these classes sit in the components layer, a component's own utilities win over them; a rule that must beat a utility, like the dark text color of `.glow-plain`, goes outside the layers.

The Studio settings panel (`routes/studio/editor/inspector.svelte`) has no tabs. It shows the preset picker, then the essentials (Brand, Font, Heading font, Corners, Density, Glass surfaces, Motion), then one All settings disclosure with every other group. Each group component takes an `essentials` prop: with it, the component renders only its essential rows; without it, the component renders its groups and adds the essential rows back only while the settings search is active, so a row never shows twice. To add a setting, put it in its group, not in the essentials. To promote one to the essentials, move its row into the group's `essentials` branch and its `filter.active` branch together, and drop another essential.

The homepage renders everything with the first response. Do not lazy-mount, defer, or idle-load any part of it, including the showcase and the demos. Its stats must be counts read from the source (`components`, `catalogSections`, `builtInThemePresets`). Only the move between the homepage and another page animates; docs-to-docs navigation stays instant.

The site's neutral palette comes from `app.css`, which overrides `--mielui-neutral-0` and `--mielui-neutral-10` only while no `#mielui-live-theme-style` tag exists. Change the docs page and card colors there, not in `ui.css`, so the library's default theme and live Studio themes stay untouched.

## Hover, press, and overlay motion contract

Hover feedback is instant everywhere, in library components and in the docs. Do not put `background-color`, `color`, `border-color`, `box-shadow`, or `text-decoration-color` in a transition just to fade a hover state, and do not reach for `transition-colors` with `--motion-duration-hover` on a hover wash. `--motion-duration-hover` is still the duration for enter and exit fades (tooltips, panels, scroll edges, focus rings on fields), so keep using it there. The exceptions are spatial: the traveling highlight and Tabs and ToggleGroup indicators keep their `--motion-duration-item` glide, and the lit glow keeps its hover light.

Press feedback animates only `transform` and `scale`, for `--motion-duration-press` (now 120ms). Button's base transition is `transition-[transform,scale]`; if you compose a pressable control, list only those properties so press timing never leaks into hover colors. In the docs, use `.press` for buttons and chips and `.press-soft` for large tiles and sidebar rows, and only when the whole element is the target.

An overlay a person toggles must reverse from its current position. Use one bidirectional Svelte `transition:` and pick the enter or exit helper from the open state inside a local function, as Sheet and Dialog now do (`transition:sheetMotion={{ side }}`, `transition:dialogMotion={[dialogIn, dialogOut]}`). Separate `in:` and `out:` directives restart from their first frame when interrupted, which made a reopened sheet jump off-screen and snap at the end. Never gate input on an animation. Popover, menus, HoverCard, and DatePicker still use separate `in:panelIn` and `out:panelOut`; switch them the same way when you touch them.

In the docs, `html` paints `--color-background`, and the root layout copies the computed page color into both `theme-color` meta tags whenever the mode class or a live theme changes. Keep the static tags in `app.html` for the first paint, and do not set `theme-color` anywhere else.
